OmniParser and the C# workspace

What the checked-in model does, how the C# detector calls it, how to run the demo, and how to scaffold new C# console or Windows Forms projects in VS Code.

Windows.NET 10ONNX Runtime + DirectML
Scope: this workspace contains OmniParser's icon-detection model and a C# inference wrapper. It does not contain the complete OmniParser pipeline, caption model, or a sample screenshot.

What OmniParser does

OmniParser is a screen-parsing system intended to turn GUI screenshots into structured elements that a vision-capable agent can reason about and ground actions against. The upstream project combines interactive-region detection with icon descriptions; it is a perception component, not by itself a complete computer-use agent.

1. ScreenshotPixels from a desktop or application window.
2. Detect regionsFind candidate controls and icon regions.
3. Describe iconsA caption model can add functional descriptions.
4. Ground actionsAn agent uses parsed elements to choose screen coordinates.
In this C# sample, only step 2 is implemented. It returns boxes and numeric class IDs; it does not caption icons, parse text, decide what to click, or perform mouse/keyboard actions.

The upstream repository and model releases evolve independently. Follow their README and model card for the complete setup, required weights, model versions, and licensing. The local .pt file is a PyTorch checkpoint; this C# program loads the adjacent model.onnx file instead.

Run the C# detector

From the workspace root, provide a screenshot path. A confidence threshold is optional and defaults to 0.4.

dotnet run --project onnx_runner/onnx_runner.csproj -- "C:\path\to\screenshot.png"
dotnet run --project onnx_runner/onnx_runner.csproj -- "C:\path\to\screenshot.png" 0.55

The program looks for omniparser_v2/icon_detect/model.onnx by searching upward from both the current working directory and the executable directory. It prints a count followed by class ID, confidence, and [x, y, width, height] for each detected box.

Inference currently requests the DirectML execution provider on device 0. A Windows DirectML-compatible GPU/runtime is required; there is no CPU fallback in UIControlDetector. No screenshot is checked into this workspace, so supply your own image.

Detector behavior and assumptions

  1. Loads the image as RGB and remembers its original dimensions.
  2. Resizes it directly to 640 x 640, then builds a float tensor shaped [1, 3, 640, 640] with RGB values scaled to [0, 1].
  3. Runs the model using the first input name and reads the first output as a float tensor.
  4. Interprets output as [1, features, anchors]: center-x, center-y, width, height, then class scores. The highest score above the threshold becomes a box.
  5. Scales box coordinates back to the original image dimensions. The class value printed is a numeric index, not a human-readable label.
This is a small inference demonstration, not a full post-processing port. It stretches images rather than preserving aspect ratio, assumes one specific output tensor layout, and does not perform non-maximum suppression or map class IDs to labels. Validate those assumptions against the exact ONNX model before relying on detections.

The session and inference result are disposed with using; the detector itself implements IDisposable. If the ONNX model's input/output names, dimensions, or preprocessing contract differ, update the wrapper to match the model metadata.

Create C# projects from VS Code

These workspace tasks call the installed dotnet new templates. Use Ctrl + Shift + P, run Tasks: Run Task, select a task, and enter a project name. New project folders are created under the workspace root.

Console project with explicit Main

Select New C# Console Project (static Main). The task runs the console template with --use-program-main, producing a conventional Program class and Main method instead of top-level statements.

dotnet new console --use-program-main --output <workspace>/<project-name>

Windows Forms project with Form1

Select New C# Windows Forms Project (Form1). The standard WinForms template creates Form1.cs, its designer file, a project file, and the WinForms startup code in Program.cs.

dotnet new winforms --output <workspace>/<project-name>

WinForms is Windows-specific. These tasks are workspace-scoped; they do not change VS Code's built-in project wizard defaults or other workspaces. A newly generated project is not automatically added to the existing solution. To add one, run:

dotnet sln onnx_runner.sln add <project-name>/<project-name>.csproj

Troubleshooting

Image not found

Pass an existing image path. Paths with spaces should be quoted. Supported image formats depend on ImageSharp's installed codecs.

Model not found

Keep omniparser_v2/icon_detect/model.onnx in the workspace tree, or change FindModelPath() in Program.cs to use a configured path.

DirectML or provider initialization error

Confirm the Windows machine has a compatible DirectML device and matching native ONNX Runtime files. For a CPU-only path, add an explicit CPU session option and make the execution provider selectable; the current constructor always requests DirectML.

No detections or unexpected boxes

Check the model's expected preprocessing, input size, output tensor shape, confidence semantics, and need for non-maximum suppression. The current parser is intentionally narrow and assumes the output layout listed above.

New task does not appear

Make sure VS Code opened this workspace folder, then run Tasks: Run Task again. The required templates are the installed console and winforms .NET templates.
